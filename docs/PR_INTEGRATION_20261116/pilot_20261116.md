## Corrections (parent analysis)

1. **Cost per pass compared mismatched populations.** The original table divides
   segments' 14 graded tasks *plus* the interrupted task's retained reservation
   by 13 passes, against baseline's 24 tasks. On the **same 14 completed tasks**,
   using settled actual usage only (`pilot/pilot_matched.json`):

   | matched 14 | baseline | observe | segments |
   |---|---:|---:|---:|
   | passes / FA / FR | 12 / 1 / 0 | 9 / 1 / 0 | 13 / 0 / 1 |
   | model calls / script steps / tool steps | 33 / 29 / 32 | 25 / 35 / 23 | 53 / 67 / 53 |
   | settled USD | 0.011592 | 0.008546 | 0.015438 |
   | settled USD per pass | 0.000966 | 0.000950 | 0.001188 |
   | wall total / mean / median (s) | 165.2 / 11.8 / 10.4 | 135.5 / 9.7 / 6.0 | 210.9 / 15.1 / 14.2 |
   | wall per pass (s) | 13.8 | 15.1 | 16.2 |

   Segments cost ≈1.33× baseline in total and ≈1.23× per pass, with ≈1.6× the
   model calls and ≈1.17× the wall time per pass. The interrupted 15th task
   (`dev4_form_lambdatest_input`) is excluded above: segments settled $0.000060
   on it plus the **$0.012660 retained reservation**, which is a pre-call
   upper bound, not measured usage. Baseline and observe both passed it.
2. **`dev3_value_exif_gpsaltref` was not a correct rejection of the same answer.**
   The two runs generated different outputs. Baseline claimed a prose snippet,
   its runtime said PASS and the grade failed it (FA). Segments extracted the
   whole GPS tag table; the runtime returned UNKNOWN ("Script result metadata
   exceeds tool-result budget"), while the unchanged grade reports
   `page_answer_success: true`, which is a **false reject** by the report's own
   definition. Removing the FA here is a different-output effect, not evidence
   that segments rejects wrong answers better.

## Decisions

- **#74 observe-first: PARK** as an accuracy candidate. It lost three tasks and won none in repetition 1, which is the opposite direction from the plan's +2 bar. It also lost value, search and form. Its first-script pass count went from 3 to 7, false accepts from 2 to 1, and cost and time were about the same. The code can stay off by default if it is integrated for its correctness tests, but no accuracy benefit should be claimed.
- **#82 segments: KEEP_OPT_IN (default off); accuracy INCONCLUSIVE.** On the 14 matched tasks it scored +1 with no paired loss and 0 false accepts against 1 for baseline. It had one new false reject, ~~about twice the cost per pass~~ about 1.23× the settled cost per pass on the matched 14 tasks (see Corrections), and higher median wall time. Its coverage is incomplete: no spa tasks, 2 of 6 form tasks, and no repetition 2. That falls short of the plan's evidence bar for promotion. It stays opt-in, consistent with its offline correctness tests and historical evidence.
- **#81:** merged cleanly into the frozen runtime and passed the focused checks (see the pre-paid check above). It is correctness work, as already recommended in `test_verifier_title.md`. No accuracy claim is made from this pilot.
