Ways to run the owned loop

Computer use is slow because each step re-sees the screen with a large model and holds the pointer. Owning the loop, shape 1, is the place to stand. These are different ways to take a step inside it. None of them is settled.

The surface is still open: the browser if the pointer should stay put, the Windows desktop if the pain is Cursor on this PC. The switch on the clock changes that picture. The lengths on the clock are a sketch, a scale model of one export, not a measurement on this machine, and they do not price these ways.

Rules, then a direct click

When the role and the name are unique, click that control. No model.

Cost. The match itself, tens of milliseconds, and no model bill.

Fails when the name is shared or missing. This way does not guess a neighbour.

A lightweight decider, then a fast text model

A small decider only picks the tier. A fast text model then chooses from the control list. The decider does not click.

Cost. A small decision, then one short text call. No image.

Fails when the words cannot tell the controls apart. Icons and canvas are the usual miss.

A fast vision model on a crop

Only for an icon or a control with no name. The model sees a crop, not the whole screen.

Cost. One small vision call on that crop.

Fails when the crop misses the control, or the icon is ambiguous. Unnamed controls show up sooner on the Windows desktop than in the browser.

One frontier model, then the batch

One frontier model writes a batch of verbs from the tree. The executor runs that batch until an assertion fails, and then it stops.

Cost. One large model call for the batch. The clicks and the waits after that are the page, not another model.

Fails when the batch was wrong, the page moved, or the assertion does not hold. It does not click through a failed check.

Skill replay

After a traced success, store the script and a fingerprint of the page. Replay it while the fingerprint matches. When the page changes, the skill expires.

Cost. A hit is no model call. A miss falls through to another way. A script past its expiry is a wrong click at full speed, so it does not run.

Fails when the fingerprint misses a real change, or matches too loosely. Expiry is the guard.

A plugin in Cursor or Claude

Cursor or Claude can call this runtime. The plugin is a client. It is not the loop. Their agent may ask for a verb. The executor still owns the click.

Cost. Their model spends a call deciding to ask. The action is a verb on a numbered control, not another screenshot.

Fails when they skip the verbs and look at the screen again. The long bars stay, and this is no longer the owned loop.

The machine further down is what these ways would share. It is not built. The default marks are a proposal you can change, not a decision that one way has won.

What I would change

The ways above are open. This section is one proposal for an order, not a decision that the others are out.

Ship the browser verbs first, on the person’s real Chrome. An agent they already use can call them the same week. Our planner uses those same verbs once the task set exists.

Keep one frontier model in the loop. Add a smaller grounder when a trace shows the planner spending time on obvious clicks, and a vision crop when the control has no name.

Start in the browser if the pointer should stay put. Flip the switch above if the pain you actually feel is Cursor on the desktop. The verbs stay. On Windows the pointer still moves for some controls, and unnamed icons still need a look.

Store skills after you have traces worth replaying, with a fingerprint of the page, and expire them when that fingerprint changes.

Leave interception as its own product. It never chooses the model, so the red bars stay red.

What has to stay true

Pay, send, and delete wait for a person. A replay cannot submit the same form twice.

Mail, balances, and message bodies are stripped from the tree before a model sees it, unless the task asked for that field.

A skill stores a fingerprint of the page and expires when the page changes. A stale script is a wrong click at full speed.

Extra tabs, popups, downloads, file pickers, and login walls are states the executor knows. They are where browser agents get lost.

A person can pause, do the step, and have that correction saved.

Chrome warns when we attach. The desktop shows the pointer when we cannot avoid it. Both stay visible.

Every change re-runs the task set. A shorter clock counts when success holds.
